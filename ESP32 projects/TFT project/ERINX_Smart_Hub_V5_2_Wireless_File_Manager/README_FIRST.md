# ERINX SMART HUB V5.2 — WIRELESS FILE MANAGER

This firmware builds on **V5.1.3** (TFT + touch + weather + clock + DHT11 + JPEG photo viewer + custom EVM video player + Wi-Fi selection). It adds a **professional responsive browser interface served by the ESP32-S3 itself**. No cloud account or SD-card removal is needed to add media.

## 1. Firmware installation

1. Extract the ZIP to your computer.
2. Open `Firmware/ERINX_Smart_Hub_V5_2/ERINX_Smart_Hub_V5_2.ino` in Arduino IDE, and make sure BOTH `PageTypes.h`, `FilePortal.h`, and `FileManager.h` are in that **same sketch folder**. Do not open a temporary unsaved copy without the headers.
3. Keep your **existing tested `TFT_eSPI/User_Setup.h` and existing wiring**; no hardware changes are required.
4. Install ArduinoJson v7, TFT_eSPI, TJpg_Decoder, DHT sensor library by Adafruit, and Adafruit Unified Sensor. WiFi, Preferences, WebServer, FS, and SD_MMC come with the ESP32 board package.
5. Use **Tools > Board > ESP32S3 Dev Module**, **Flash Size 16MB**, **PSRAM OPI PSRAM**, same COM port and other settings as your V5.1.3. Click Verify, then Upload.
6. Use the touchscreen **Settings > Wi-Fi Setup** to connect to a **2.4 GHz** Wi-Fi network. The PC and ESP32 should be on the same LAN.
7. Go **back to Home, then open Settings again** after Wi-Fi connects. Look under the MICROSD card for:
   - `WEB: http://192.168.x.x` — your actual ESP32 LAN address;
   - `PIN: 123456` — your actual random 6-digit PIN (the example is not your real code).
8. On your laptop, open the **exact address shown on the ESP32** using `http://`, not `https://`, and enter the PIN shown on its Settings screen.
9. Choose Photos or Videos, Browse/drag files, and Upload. Switch to Media Library to browse or delete. Return to Gallery/Video on the TFT to see the new files.

## 2. What can be uploaded?

| Type | Allowed | Destination | Per-file limit |
|---|---|---|---|
| Photos | **Baseline** JPG/JPEG | `/photos/` | 6 MiB |
| Video loops | `.evm` generated by bundled converter | `/videos/` | 60 MiB |

**No direct MP4 upload or MP4 playback.** The existing video player decodes silent JPEG frames from `.evm`, so convert source videos on your PC first. Photos should be 320×480 baseline JPEG for best compatibility. `.png` must be converted on PC.

Files must use simple Latin filenames containing letters, digits, spaces, underscores, hyphens and dots, e.g. `Nature_01.jpg` or `Morning Loop.evm`. The file manager does not overwrite existing filenames. Rename the file before uploading it again. Upload to the fixed installed card — no SD eject needed.

The web interface can list at most 80 entries per category. The existing TFT Gallery supports up to **40 photos** and the TFT Video Browser up to **24 clips**.

## 3. Convert files on Windows PC

Install Pillow if necessary:

```powershell
python -m pip install pillow
```

To convert images in `Documents\MyPhotos` to baseline JPEG:

```powershell
python .\convert_photos.py "$env:USERPROFILE\Documents\MyPhotos" "$env:USERPROFILE\Documents\ConvertedPhotos"
```

For MP4 conversion, install FFmpeg first:

```powershell
winget install --id Gyan.FFmpeg -e
# Restart terminal
ffmpeg -version
python .\convert_videos.py "$env:USERPROFILE\Documents\MyVideos" "$env:USERPROFILE\Documents\ConvertedVideos" --width 160 --height 240 --fps 5
```

The `160×240 at 5 FPS` example is conservative: observed rendered FPS on this hardware was limited. It does NOT guarantee 5 FPS video playback. Higher resolutions can be slower. Upload the resulting `.evm` file through the ESP32 web page.

## 4. Important behavior and security

- **Access PIN changes at every ESP32 boot.** It is visible on the physical Settings screen; the web app never stores the PIN on disk. Closing or refreshing the browser asks you to enter it again.
- The webpage uses ordinary local **HTTP, not HTTPS**. A person with access to a compromised/shared Wi-Fi network might intercept traffic/PIN. Use only a trusted home/hotspot network; **do not expose port 80 to the internet or forward it through your router**.
- Incorrect PIN entries are rate-limited after eight attempts for 30 seconds. The Wi-Fi credentials saved in NVS by earlier versions remain unchanged.
- The file server runs only after Wi-Fi connects. It does not create its own hotspot.
- **Leave the VIDEO PLAYER screen on the TFT** before viewing/uploading/deleting files in the web manager. SD access during frame playback is blocked to avoid contention. Using large transfers may slow UI responsiveness.
- Uploaded data first goes to `.erinx_incoming` on the SD card. It is checked, and then renamed to its final path. Incomplete temp files are cleaned up on next boot.
- Browser thumbnail images and HTML/CSS/JS are served by the ESP32 itself; no external CDNs are required.
- Reconnect the browser using the new IP and PIN after a board reboot or Wi-Fi network change.

## 5. Troubleshooting

**Website does not open:** Confirm Wi-Fi CONNECTED in Settings, PC on same Wi-Fi/LAN (not a guest network with client isolation), use ESP32 IP and `http://` with no special port. If IP does not appear, revisit Settings after connection completes.

**Invalid PIN:** Look for `PIN:` in Settings. PIN changes after reboot. If locked out, wait 30 seconds. The server does not expose the PIN in Serial Monitor.

**Photos appear black/not supported:** Convert with `PC_Tools/convert_photos.py` to baseline JPEG, 320×480.

**EVM won't play:** Use the bundled `convert_videos.py`, avoid progressive JPEG frames or huge frames, enable OPI PSRAM in board settings. Current player FPS may be limited by the TFT SPI bus.

**Compile errors mentioning SD_MMC:** Make sure `ESP32S3 Dev Module` is selected (not generic ESP32 Dev Module) and selected Core provides SDMMC; V5.1.3 code includes checks.
